# GoalWeave

一个**本地跑的个人任务板**：今天做什么、什么时候做、为什么做，都摊在同一个界面上，不用在待办清单、课程表和笔记本之间来回切。
（界面上还沿用「任务板」这个叫法，仓库名叫 GoalWeave。）

## 为什么叫 GoalWeave

**Goal + Weave：把目标和日子织在一起。**

大部分待办工具的毛病是「目标」和「今天」是两张皮 —— 长期计划写在目标页（或者脑子里），每天要干什么写在任务页，
中间那段「这个月该推进哪几步、今天该学哪一段」全靠人肉对齐。这个工具就是冲着这段缝来的：

- **目标不是一句口号**，会被拆成一条条知识点，带前置依赖（DAG），排成拓扑序；
- **排期不是让你手填**：按「完成时间 + 每周投入」算出每个知识点该花多久，再自动**织进**日程表的空段里 ——
  所以「周一晚上 19:30–21:00 学什么」是被算出来的，不是拍出来的；
- **反过来也成立**：日程格子里的完成情况、过期没做的、被卡住的下游，都会回到目标进度上。

所以四个页面看起来是四件事，其实是同一张网的四个切面：**Goal 决定要做什么，Weave 决定什么时候做**。

四页分工：

- **首页**（`index.html`）：顶上一张一周日程表，下面是今日任务和今日推荐的知识点
- **任务**（`tasks.html`）：任务列表、分类与筛选、回收站，以及助手对话框和聊天记录
- **目标**（`goals.html`）：长期目标 → 知识点大纲 → 学习路线图 → 自动排进日程表
- **设置**（`settings.html`）：兴趣标签（含每日推荐开关）、助手配置与导入导出、外观（密度 / 字号）

新建任务、新建目标都收在右下角的 **＋** 里；主题（跟随系统 / 亮色 / 暗色）在页眉右上角的圆按钮上循环切。

几条自己定的规矩：

- **数据是你的**：任务、目标、日程、聊天记录都在本机 `config/data.json` 里，换浏览器、清站点数据都不丢。不想要后端也能只当纯静态页面用（各功能照旧，只是少了模型和跨设备）。
- **不联网也能用**：没配模型时，拆任务、排学习计划、挑推荐知识点都有内置方案兜底，不会卡在「请先配置」。
- **不塞你不想要的东西**：每日推荐能整个关掉；说过「不想学」的会记下来，不再推。
- **第一次打开会走一遍引导**：要不要每日推荐 → 挑几个兴趣方向 → 配模型，三步都能跳过，之后在设置页里也能改。

## 怎么跑

**必须用本地服务打开，不要直接双击 HTML。** 设置里的密码门用 WebCrypto 的 PBKDF2，只有 `https` 或 `localhost` 下浏览器才给用 `crypto.subtle`；`file://` 打开会提示「这个浏览器不给用加密接口」，助手配置就没法改。

```powershell
.\serve.ps1
```

会起 `http://localhost:8777/` 并自动开浏览器。默认走**后端**（`server.py`）：静态文件、配置存储、技能运行都在同一个 origin，不用再管跨域。想换端口：`.\serve.ps1 -Port 9000`；想退回原来那套纯静态服务：`.\serve.ps1 -Static`。

后端对静态文件也发 `Cache-Control: no-store`，所以改完 HTML/JS/CSS 刷新一下就是新的，不用手动清缓存（`-Static` 起的纯静态服务没有这个）。

想让手机也能打开（连热点/同一 WiFi）：`.\serve.ps1 -Lan`，细节见下面的「手机 / 局域网打开」。

也可以用别的办法，只要落在 `localhost` 上就行：

```bash
python server.py --port 8777     # 后端（推荐）
npx serve .                      # 纯静态，没有后端功能
```

纯静态时后端功能全部静默降级，其它功能照旧。

### 想以新用户的身份试一遍

引导（见下面的「新用户引导」）只在**本地和后端都没有数据**时出现，所以别删自己的库，另开一个**空库分身**就行 ——
`--data` 能指一份不存在的数据文件，站点目录和代码都是同一份，只是换了份数据：

```powershell
.\serve.ps1 -Data config\data.fresh.json -Port 8780
# 等价于：python server.py --data config/data.fresh.json --port 8780 --open
```

启动那行会写明 `数据文件：… ← 分身库，正式数据没动`，看到它就说明没碰正式数据。**记得换个端口**
（8780 之类）：浏览器的 `localStorage` 是按「协议 + 域名 + 端口」分开存的，同端口的话本地那份偏好还在，不算干净的新访客。

1. 打开 `http://localhost:8780/`，三步引导会自己弹出来：要不要每日推荐 → 挑几个方向 → 配模型。
2. 想再看一遍：控制台里 `localStorage.clear(); location.reload();`，再把分身那份数据清掉 ——
   `curl -X DELETE http://localhost:8780/api/data`（或停掉服务后删 `config\data.fresh.json`）。
3. 玩够了就把这个实例停掉、把 `config\data.fresh.json` 删掉，正式数据从头到尾没被碰过。

两个细节：

- **助手配置是共用的**：`.env` 不分身，所以分身里走到「配模型」那步会看到已经填好的接口地址和模型名（密钥框留空保存**不会**覆盖存着的密钥）。想连这一步也当新用户，把 `.env` 临时改名成 `.env.bak`，玩完改回来。
- **答过之后才会推荐**：引导没答复之前，既不会先生成一条推荐任务，也不会拿你存着的密钥去问模型。

## 手机 / 局域网打开

手机连上电脑的热点（或同一个 WiFi）之后，用后端启动时加 `--lan`：

```powershell
python server.py --lan
```

启动时会直接把能用的地址打出来，手机浏览器里输热点那个就行：

```
  已监听所有网卡，同一个 WiFi / 热点里的手机可以打开：
    http://192.168.137.1:8777/
  接口只放行本机和这些网段：192.168.137.0/24
```

`192.168.137.1` 是 Windows 移动热点的网关，固定不变。手机连热点时系统会提示「此网络无法访问互联网」，选**仍然连接**（热点本来就只是给手机连电脑用的）。

几点说明：

- **接口按来源 IP 放行**：本机 + 热点网段（`192.168.137.0/24`）能用 `/api/*`，其它地址只能看到静态页面，读接口是 `403`。这台机器往往同时在校园网 / 公司网里，加这一层是为了别被人随便扫到数据。要放别的网段进来就加 `--allow 192.168.1.0/24`（可重复、可逗号分隔）。
- **明文密钥只给本机**：从非本机 IP 请求 `/api/config?reveal=1` 只返回打码的密钥，导出 `.env`（`GET /api/config/env`）直接 `403`。
- **手机端不用配助手**：模型调用走电脑上的后端，密钥不出这台机器。
- 要是手机打不开，多半是防火墙：跑后端那个 `python.exe` 得有一条入站放行规则（Public 配置）。没有的话用**管理员** PowerShell 加一条（路径用 `where.exe python` 查）：

  ```powershell
  New-NetFirewallRule -DisplayName "taskboard 8777" -Direction Inbound -Protocol TCP -LocalPort 8777 -Action Allow
  ```

## 数据存在哪

数据由**后端保存**，所以同一台电脑上换浏览器、清站点数据，看到的都是同一份：

| 位置 | 内容 |
| --- | --- |
| `config/data.json` | 全部数据：任务、回收站、长期目标与知识点、日程表（`schedule.busy` = 用户划掉的非空闲段）、分类、设置、兴趣点、当日推荐（带一个自增的 `rev` 版本号） |
| `localStorage["spasre-tasks-v1"]` | 同一份数据的兜底副本，只在后端不可达时用（比如 `serve.ps1 -Static` 起的纯静态服务） |
| `.env`（项目根目录） | 助手配置（接口地址 / 模型 / 密钥），后端读写的就是这个文件 |
| `localStorage["spasre-theme"]` | 明暗模式偏好（`light` / `dark`；没这项就是跟随系统） |
| `localStorage["spasre-look"]` | 外观：密度（`comfy` / `compact`）和字号（`small` / `normal` / `large`） |
| `localStorage["spasre-board-view"]` | 任务页挑的筛选（页签 / 分类 / 紧急度 / 时间范围） |
| `localStorage["spasre-sched-draft"]` | 时间段改了还没按「保存」的那份草稿 |
| `localStorage["spasre-sched-week"]` | 日程表正在看的是哪一周 |
| `sessionStorage["spasre-agent-key"]` | 助手密钥（勾了「记住密钥」就存进数据里，跨浏览器都在） |

一句话：**凡是能改的数据都在 `data.json` 里**（连兴趣标签、聊天记录、每日推荐、非空闲段、时间段都在 `settings` / `chat` / `daily` / `schedule` 里），本机只额外存上面这几个纯界面的偏好 —— 换个浏览器看，数据和这些偏好都能找回来（密钥除外，那是本机会话的）。

同步怎么走：

- 打开页面先用本地那份画出来，接着拉后端：后端有数据就以后端为准重画；后端是空的而本地有数据，就把本地这份推上去（第一次迁移）。
- 之后任何改动都是「先写本地，再防抖 400ms 推后端」。
- 页面每 5 秒轮询一次，`rev` 比本地新就整份换掉并重画 —— 所以在手机上加一条任务，电脑上最多 5 秒就能看到。
- 写盘偶尔会失败（Windows 上目标文件被杀软 / 索引器短暂占住，`os.replace` 会报 WinError 5）：后端会退避重试几次，前端推不上去也会隔 700ms 再试两次，别让改动悄悄丢掉。
- 后端没起（纯静态）时全部逻辑照旧走本地，不会报错。

`.env` 和 `config/data.json` 里都是明文（密钥就在 `.env` 里），**别外传、别提交**（仓库的 `.gitignore` 已经挡住这两个）。

> 这个 `.env` 只是任务板应用自己的配置文件（`server.py` 自己读、自己写），**不是给终端用的环境变量文件**。
> 所以 `.vscode/settings.json` 里把 `python.envFile` 指到了一个不存在的路径、并关掉了
> `python.terminal.useEnvFile`：免得 VS Code 的 Python 扩展把里面的 api key 注入到集成终端里
> （那样随便哪个脚本都能读到你的密钥）。想让别的 Python 项目用 shell 环境变量时，把这两行改回去就行。

## 备份 / 换台机器

数据全在 `config/data.json` 一个文件里，助手配置全在 `.env` 里，搬这两个就搬走了一切：

- **备份**：复制走就行。`config/data.json` 是纯文本 JSON（`{ rev, updatedAt, store }`），坏了也能自己打开看。
- **换台机器**（或者换目录）：把整个目录带过去，或者只带 `config/data.json` + `.env`，放到新机器上同样的位置。
- **清空看板重来**：设置页「数据」那块点「清空数据…」，输入 `确认清空数据` 就清（后端那份一起清，然后回到新用户引导）。命令行也行：`curl -X DELETE http://localhost:8777/api/data`，或者停掉服务后删 `config/data.json`。
  只想清助手配置的话，设置页的助手卡片里有「导出 / 导入 .env」，导出的文本里也带着密码哈希。
- 想在没起后端的时候也能看到数据，浏览器里那份兜底副本（`localStorage["spasre-tasks-v1"]`）跟后端这份是同一份结构，
  两边都有数据时会以后端为准。

## 设置页（页眉的「设置」）

一个独立页面，放四类东西：

- **外观**：**密度**（宽松 / 紧凑）、**字号**（小 / 标准 / 大）。两项都**只存这台设备**（`localStorage["spasre-look"]`，跟主题一个思路，不走后端），改完立刻生效，刷新时由 head 里那段内联脚本先落好、不会闪一下。密度是给主要容器收内边距 + 日程表格子压到 84px，字号是给 `<html>` 上 `zoom`（0.92 / 1 / 1.1）—— CSS 里的字号大多是写死的 px，缩放最省事也不会漏掉哪块。
  **主题不在这里**：点页眉右上角那个圆形按钮就是 **跟随系统 → 亮色 → 暗色 → 跟随系统** 三档循环（跟随系统时不写 `data-theme`，交给 CSS 的 `prefers-color-scheme`）。**图标跟当前那一档走：半圆=跟随系统、太阳=亮色、月亮=暗色**，悬停提示会写清现在是什么、点一下会变成什么。
- **兴趣标签**：回车加、点标签删；输入框和上面的标签之间留了空隙，自己输入的标签加完**马上**出现在标签行里（不用等页面重画）。下面还有「猜你感兴趣」：第一次进来先推一批预设方向；你选了/输了一个，它就接着推 **5 个相关的**（换一批可以重来），鼠标停在标题上能看到这批是 AI 出的还是本地词库兜的。推荐由后端技能 `interest.suggest` 出，没配模型或后端不在就退回内置词库，页面不会空着。
- **每日推荐开关**（就在兴趣标签这块）：勾上要满足**至少 3 个自己挑的兴趣**，不够会弹「先挑几个方向」——挑 3 个以上（点一个，相关的会铺在旁边，**也能自己输入**）或者**跳过**。**跳过不会替你填标签**，只是先随机推；之后按下面「兴趣怎么长出来」那条慢慢推。
- **兴趣怎么长出来**（跳过标签之后）：看**你这几天学完的每日任务**（回收站里 `reason=done` 的每日推荐任务标题），攒够 2 条就让模型归纳 1-3 个方向（没配模型就在宽泛方向里按标题命中兜），存进 `settings.autoInterests`，界面里是**虚线蓝色**、跟你自己挑的区分开。**换掉的那些**（`store.dailySeen`）反过来当反例：不推、也不当兴趣 —— 点「换一个」时会立刻把沾边的自动标签摘掉，下次归纳也会避开。一天最多归纳一次（`settings.interestInferredOn`）。
- **助手**：配置（接口地址 / 模型名 / 密钥 / 自定义接口）+ 密码门 + 导入导出 `.env`。原来的「导出 .env / 导入 .env」按钮也搬到这里了。
- **数据**：「清空数据…」—— 要先把 `确认清空数据` 这句话原样打一遍才放行（回车也行）。点了之后任务、回收站、目标与知识点、日程、聊天记录、兴趣标签、每日推荐全清掉，**后端那份也一起清**（不清的话刷新又被拉回来），然后跳到首页**重新走一遍新用户引导**。
  **留着不动**的是配置和本机偏好：助手里的接口地址与密钥（`.env`）、主题 / 密度 / 字号（只存这台设备）—— 想连助手配置一起清，去上面「助手」那张卡片里改。

（原来那块「任务板」设置——默认分类 + 每天加一条推荐知识点——已经去掉了：默认分类固定用「学习」，推荐开关挪到了「兴趣标签」那块。）

任务页那边只剩 **对话框 + 聊天记录**：问过什么、答过什么都在记录里（存 `store.chat`，最多 40 条，跟着看板数据一起走后端），旁边有个「清空」。

## 助手

助手区块按「填了什么用什么」的优先级工作：模型接口 → 自定义接口 → 内置规划。

- **内置规划**：什么都不填就能用，纯前端、不上网。用换行、分号、句号或「1. 2. 3.」拆分；认日期（今天/明天/后天/本周/下周/周三/10-12/2026-10-12）和紧急程度；问句会去读任务板再回答。
- **接自己的模型**：填「模型接口地址」「模型名」「密钥」，点「测试连接」。走 OpenAI 兼容格式，会自动补 `/chat/completions`；DeepSeek、Moonshot、Groq、SiliconFlow、OpenAI 都能用，本地模型填 `http://localhost:11434/v1`（Ollama）这类地址，密钥留空即可。接口不让网页直连（CORS）时不用管——起了后端（`server.py`）它会自动代发，也可以把地址指向自己的代理。配好之后设置页那张卡片就显示一行「已连接 · 模型名」。
- 改配置要点设置页里的「改配置」，第一次会让你先定一个密码（至少 4 位）。密码只存 `PBKDF2-SHA256`（150000 轮、16 字节随机 salt）的派生值和 salt，原文不落盘。

## 新建任务 / 分类

- 右下角 **＋** 打开「新建任务」：任务名、**分类（下拉选）**、紧急程度、日期。
- **分类是个真下拉框**：列着四个默认分类 + 用过/自己加过的分类；最后一项是 **「＋ 新分类…」**，选它会在旁边展开一个输入框填名字，提交时自动登记成一个新分类（以后下拉框里就有它了）。
- 没有分类在用的自定义分类会留在下拉框里（方便复用）；点任务卡片右边能改分类，改的也是同一个框。

## 长期目标是怎么排出来的

新建目标是一个四步向导（右下角 ＋）：**学习目标 → 预期完成时间 → 大纲 → 每日任务**。

**进第三步就一次做完，没有单独的按钮**：生成知识点 → 拼出大纲 → 画学习路线图，状态行里报进度（例：`14 个知识点 · 模型生成 · 学习路线图 3.5 秒`）。三步里的第一步由 `generateNodes()` 完成：**模型 → 后端 `learn.curriculum` 技能 → 内置模板**，逐级回退。

- 每个节点带一条**教程链接**（模型挑的，或技能阶段资料来源），生成后可以在下面的列表里**改标题、改链接、删节点**，上面的大纲跟着变；这时挂着的那张图会被标成旧的，旁边出现「重新画一张」。
- 学习路线图交给后端的 `diagram.roadmap`（Archify）：画成一张能缩放、能导出的 HTML，画完就在向导里内嵌预览。地址存进目标的 `diagram` 字段，**目标卡上的「学习路线图」点一下就在本页展开**（同一个 iframe，不新开页面，展开状态记在 `state.openDiagram`）。
- **编辑已有目标**时，进第三步直接摆出存好的那张图（不重跑）；知识点重生成过、图对不上了，才会重新画一次。
- **按钮只在需要时才出现**：平时第三步只有状态行 + 大纲 + 图；出错了（后端没起、Archify 没过校验）或在上面改了知识点，才会冒出一个「重试 / 重新画一张」。
- **第四步是排期**：先按「完成时间 + 每周投入」算这次要花多久（`每周小时 × 天数 ÷ 7 ÷ 知识点数`，半天取整），再把每个知识点填进日程表的空段里。**知识点数不能超过这段日子的天数**——超了第三步不放行，会直接说「12 个知识点，可用只有 5 天」。
- 知识点内部是一张 **DAG**：节点是知识点，边表示「先学这个才能学那个」；页面上只把它写成文本大纲。
  - 模型给回来的依赖会先清洗：认不出的人、指向自己的、重复的、成环的边全部丢掉（成环用 DFS 找回边切断）。
  - 节点按**最长路径**分层，同层横排居中，边只从上一层连到下一层。
  - 排期按拓扑序来，前置一定排在后继前面。
- **没配模型**：先试后端的 `learn.curriculum` 技能（后端在的时候，它会按目标复杂度决定要不要先查资料），技能没跑通再走内置模板，按「打基础 → 上手练习 → 深入原理 → 综合实践 → 输出总结」五步排，再从内置文档目录里挂几条资料。
- **配了模型**：把目标 + 补充说明发过去，要求只输出 `{"reply", "nodes":[{"title","brief","deps","links"}]}`；模型没给出可用的东西时，自动按「技能 → 内置」往下退。
- 节点上的「资料」角标弹出延伸阅读，用的是内置的推荐阅读目录（LLVM / Clang / GDB / C++ / MDN / Jekyll 等 24 条，写在 `assets/js/tasks.js` 的 `ARTICLE_SOURCES` 里）。

## 日程表

日程表在**首页顶部**，一天切成几段，**分段直接在网格上改**：点左边的行首标签（比如「19:30–22:30」）就在下面弹出这一段的开始 / 结束 —— **直接手输就行**（`2130` / `930` / `9` / `21:30` 都认，回车或点别处生效），改完按 **「保存」**；面板里还有「删掉这段」，要加段就用右上角的 **「添加时间段」**。默认四段：

| 段 | 时间 | 时长 |
| --- | --- | --- |
| 1 | 07:00–09:00 | 2 小时 |
| 2 | 09:00–12:00 | 3 小时 |
| 3 | 14:00–17:30 | 3.5 小时 |
| 4 | 19:30–22:30 | 3 小时 |

- **规则**：一段接一段、不能重叠（前一段的结束 ≤ 后一段的开始），结束要晚于开始。
- **改了先存在本地，按「保存」才写进数据**：改动先落在「草稿」里（存 `localStorage.spasre-sched-draft`），网格照着草稿画 —— **刷新、切页、点「非空闲」、改任务都不会丢**。顶部提示行会写一句「时间段有改动还没保存」。
- **「保存」= 校验 + 按开始时间排序 + 落盘**：点了之后先按开始时间把段排好再存，**存好这块设置面板就自己收起来**；**有重叠就不存**，面板留着让你改，只把冲突的那几行**标红**（行首时间 + 整行格子），顶部只写一句「**时间段有冲突**」，具体哪里叠了自己看红行。
- **Esc 放弃**这次改动（草稿和本地那份一起清掉，退回存着的时间段）。
- 段存在 `store.settings.segments`，**跟着看板数据一起存后端**，所以在哪台机器上改都是同一份；「添加时间段」默认从最后一段结束开始、给一小时，之后自己改。至少留一段（只剩一段时删除按钮是灰的）。
- **排期偏好从晚到早**（按时间倒序），所以加了「深夜」这种新段会自然排在最后被优先挑。
- 段被改短：已经排好的任务不会挪，只是**按时长显示**（比如 2 小时的任务落在 19:30–21:00 里就显示「19:30–21:00 · 1.5 小时」），改期时存的值会跟着收紧。
- 段被删掉：原本排在那一段上的知识点会**自动补到别的空段**（日期尽量不动），删掉的段对应的「非空闲」标记也一并清掉。
- **已经过去的时间段是灰底斜线**：格子按「日期 + 这一段的结束时刻」跟现在比，过去的就不能点（点不动、不能划成非空闲）、也不能把任务拖进去；面板里选到过去的时段会被挡下来并提示「这段时间已经过去了，换一段吧」，日期输入的下限也是今天。判到「段的结束」为止，所以正在进行的那一段仍然能用；排期时也只在还没过去的段里找位置。网格每分钟自己看一次时间，跨过整点就会自动变灰。
- **过去格子里有任务时**：
  - **做完了** → 显示「已完成」（灰掉、划掉，点不动）。
  - **没做完** → 变成一个红色按钮（「过期没做 · 点这里重排」），点一下把它排进后面的空位：先找「现在之后、下游任务之前」最早的空位；如果这段时间里没空位，就排到最早的空位、并把**下游那几个一起往后让**（状态行会说排到了哪天、连带挪了几个；一个都塞不下就提示先把一些段留出来）。
- **一个过期没做的知识点会挡住它的下游**：这些任务在网格里显示「锁定」（虚线、不能拖也不弹编辑面板），点一下会提示先重排前面那个过期任务；把过期那个重排、或者直接勾完成，下游就解锁了。任务列表里对应的任务也会挂一个「等前置重排」角标。

网格就是「一周 × 每段」：七列、每段一行，一屏看完这周排了什么：

- **一进来先看「今天」**：七列放不下时表格能横向滚，打开时会把**今天那一列贴到最左边**（窄屏上不会一进来就是半屏灰格子），点「上一周 / 下一周」切到别周时则回到那一周开头。**最左边的时间标签列是固定的**，横向滚到哪儿都知道每行是几点。
- **每格一样大**：七列等宽、每格固定 104px 高（表格 `table-layout: fixed` + `min-width: 900px`，窗口窄了就横向滚动，列宽不会再被挤小），没排任务的日子也是同样大小。
- **任务块撑满格子**：一个格子里只有一个任务时，块会占满整格（不会出现「大框里一个小块」）；两个任务平分格子高度，再多就被裁掉，拖走一个就露出来。
- **任务名多行显示**：一格一个任务时最多 4 行（12px），挤了两个以上才收成一行；时段行 11px。放不下就省略号，鼠标悬停能看到全名和完整时间（含 `· N 小时`）。

- **填法**（加新目标时统一排一次）：先把手上排好的节点占住位置（**老目标的时间尽量不动**），
  再把没排的按拓扑序**散落**到这段日子的空段里——14 个知识点、72 天大约每 5 天一个，不是连着排。
  每个知识点占一段，时长 = 这次该花的小时数（装得下就按它，装不下按段长砍）。
- **同一天有几个空段时按偏好挑**：越晚的段越先挑（倒序），这样一个目标的时间点稳定；被别的目标占了就往后让。
- **点空格 = 划成非空闲**（再点一下放开）。划掉的段排期时绕开，数据存在 `store.schedule.busy`。
- 灰底斜线的格子是**已经过去的时间段**，点不动也放不进任务（见上）。
- **点任务块 = 改它**：下面弹出的小面板能改日期、时段、时长，也能「取消安排」（改完立刻写回，任务跟着动）。
- **拖任务块 = 换时间**：直接把块拖到**空闲的格子**上松手就换过去了（拖着的时候能放的空格子会变成虚线；挪到更短的段里，时长自动按段长砍）。被划成非空闲的格子、已经有任务的格子接不住。
- **切周**：上一周 / 下一周 / 本周，范围写在中间。
- 时段会带到任务列表上：任务卡多一个「19:30–22:30」这样的角标，首页的今日任务一样能看到。
- 老数据（只有日期、没有时段的那种）进目标页会自动补一次时段，日期不动；大纲里也会把时间写进去。

## 首页的每日推荐

- **今日任务**：当天到期和已逾期的任务，点小狗直接完成。
- **每日推荐知识点**：配了模型就由模型按**兴趣点**挑一个（连同一句话说明和 1-2 条资料），返回 `{"title", "brief", "links"}`；没配模型就在内置文档目录里按兴趣点关键词挑，挑不到再按日期取一条。
- 开关在**设置页的「兴趣标签」**那块（`每日推荐：每天加一条知识点`），兴趣标签也在这块加/删（回车即添加），旁边还会让 AI 推荐标签。
- **两种推法**：
  - **按你挑的方向推**（自己挑的兴趣 ≥ 3 个）：模型/文档目录都围着你这些方向挑。
  - **随机推**（没挑、或者只点了「跳过」）：按 `store.settings.dailyDirection` 这个宽泛方向（编程基础 / 操作系统 / 大模型应用… 共 30 个）轮换着推。**跳过时不会替你填任何标签** —— 方向是从你学完的每日任务里慢慢归纳出来的（见设置页那节）。
- 生成结果按天缓存在 `store.daily` 里（跟着看板数据一起存后端），同一天不再重复问模型；打开页面时先落一条本地的，模型那条回来了再顶掉（卡片上会写「AI 推荐」还是「本地推荐」）。等新的一天，旧的按日期判过期，会重新生成。
- 卡片右上角有 **「换一个」**：
  - 说过「不想学」的会记进 `store.dailySeen`（最多 40 条），加上**已经勾掉的**（回收站里 `reason=done` 的每日推荐任务）一起：前者是**反例**（不推、不当兴趣），后者是**正例**（拿它归纳你的兴趣方向）。
  - **随机推的时候，「换一个」= 对这个方向不感兴趣** → 换下一个方向（状态行会写「换了个方向：这轮看「操作系统」」），并把自动归纳出来的、跟这条沾边的标签**立刻摘掉**。
- **打开每日推荐时要是有 3 个以上自己挑的兴趣就直接开**；不够会弹一个「先挑几个方向」的面板：挑 3 个以上（点一个，相关的会铺在旁边）或者**跳过** —— 跳过只是**随机推**，不替你填标签（兴趣靠学完的每日任务慢慢长，见上）。弹层用 ✕ 关掉不会动开关。
- **没存密钥的浏览器也能出 AI 推荐**：密钥留在跑后端那台机器上时，请求由后端代发（`bridgeChat()`），页面会先等后端探活就绪再发（拿空密钥去直连远端只会 401）。
- 想手动重来一次，控制台里 `await spasreTasks.upgradeDaily()`；失败会在 console 里留一条 warn（不然「怎么一直是本地推荐」很难查）。

## 新用户引导（第一次打开）

**只有「本地和后端都没有数据」时才出现**（自动生成的那条每日推荐任务不算），用过的人进来自动标一下 `settings.onboarded`，以后不再打扰。三步：

1. **要不要每日推荐**：`要，每天推` / `先不用` / `跳过引导`。
2. **挑几个方向**（选了「要」才有这步）：先随机给 10 个宽泛方向（**不看你已有的兴趣**，每次都不一样），点一个就把它的邻近方向铺在旁边；**自己想到的方向也能直接输入**（回车或点「添加」，也会顺着它往外铺）；**至少 3 个**才能「完成」，也可以「跳过」。上次挑过的、AI 记下来的标签会先摆出来（实心=选中的），不用猜「已选 N 个」是哪几个。
3. **配模型**（可跳过，**密码这次不用设**）：接口地址 / 模型名 / 密钥，预填 DeepSeek 那套；「保存并开始用」会走 `spasreTasks.setAgent()`。

答案落地前**什么都不会发生**：引导没答复的时候，既不会替你加那条推荐任务，也不会拿密钥去问模型（判据是 `settings.onboarded`）。
走完**先 `flush()` 把改动推到后端再跳首页**（不然那 400ms 防抖还没落盘，新页面按后端旧那份走，等于白选）。跳过第 2 步 = 随机推 + **不填任何标签**（之后按学完的每日任务慢慢推方向）。

想自己走一遍这个流程，见前面的「[想以新用户的身份试一遍](#想以新用户的身份试一遍)」。

## 后端（`server.py`）

原来任务板是纯前端的：接口地址、模型名、密钥都只在浏览器里，调模型也是网页直连（跨域不通就只能自己搭代理）。`server.py` 是个零依赖（只用标准库）的小后端，补上两件事：

1. **存配置**：把前端填的接口地址 / 模型名 / 密钥 / 自定义接口落到本机 `.env`（老版本的 `config/agent.json` 会在启动时自动搬过去、旧文件删掉）。浏览器里有配置就推上来；浏览器里没有（换了浏览器、清过站点数据）就从后端拉回来用，所以配一次就够了。**空值不会覆盖存着的密钥**，要清得显式带 `clearKey`。
2. **跑技能**：`skills/` 里每个 `.py` 就是一个技能；配好模型后技能可以借后端的模型客户端干活，绕开浏览器的跨域限制。

它同时还是静态服务器（默认和 `serve.ps1` 一个端口），所以前端 / API / 技能是同一个 origin。

**后端在页面上不露脸**：它是「看不见的管道」，状态只在设置页的「助手」卡片上带一句「本机后端在线」。技能是给功能用的，不是给人点的——哪个功能需要什么能力，就在那个功能里调对应的技能（见下面的「技能怎么被用上」）。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态，前端用它判断后端在不在 |
| GET | `/api/config` | 读配置（默认隐藏密钥，`?reveal=1` 才带明文） |
| POST/PUT | `/api/config` | 写配置，给哪些字段就改哪些 |
| DELETE | `/api/config` | 清空配置 |
| GET | `/api/config/env` | 导出 `.env` 文本 |
| POST | `/api/config/env` | 从 `.env` 文本导入（body `{ "text": "..." }`） |
| POST | `/api/config/test` | 测一下模型接口通不通 |
| POST | `/api/chat` | 转发一次 OpenAI 兼容的对话请求，body `{ prompt }` 或 `{ messages }` |
| POST | `/api/ask` | 把一段话拆成任务（配了模型走模型，否则内置规则） |
| GET | `/api/skills` | 技能清单 |
| POST | `/api/skills/<name>` | 跑技能，body 就是它的参数 |
| GET | `/api/data` | 读看板数据，返回 `{ ok, rev, updatedAt, store }`（`store` 为 `null` 表示后端还没存过） |
| PUT | `/api/data` | 整份覆盖写，body `{ "store": {...} }`，成功后 `rev` 加一 |
| POST | `/api/data` | 同 PUT（前端用 PUT） |
| DELETE | `/api/data` | 清空看板数据 |

`/api/*` 只对本机 + 热点网段开放（见上面的「手机 / 局域网打开」），其它来源返回 `403`。明文密钥只在从本机请求时才会返回。

`/api/chat`、`/api/ask`、`/api/skills/<name>` 的 body 里都可以带上 `baseUrl` / `model` / `apiKey` / `endpoint` 临时覆盖存好的配置；`/api/skills/<name>` 用 `__config__` 对象传。

### 技能

技能就是 `skills/` 目录下的模块，丢一个 `.py` 进去就会自动被发现，不用改注册表。改完已经加载过的 `.py` 也**不用重启后端**：每次取技能时会看文件时间戳，变了就重载那一个（改坏了就继续用旧的）。

```python
SKILL = {
    "name": "echo",
    "title": "回声",
    "description": "把 text 原样返回。",
    "tags": ["调试"],
    "params": {"text": "要回显的文本"},
    "requiresModel": False,
}

def run(params, ctx):
    ctx.log("被调用了")
    return {"text": params.get("text", "")}
```

`ctx` 由后端注入，能给技能这些：`ctx.chat(messages)` 调模型、`ctx.model_ready()` 看配置好没有、`ctx.config` 当前配置、`ctx.root` 站点目录、`ctx.http_get(url)` 抓网页（`raw=True` 保留 HTML 标签，用来抽标题结构；默认去掉标签只留正文。`limit` 只管**返回**多少字符，下载量另有 `max_bytes`，默认够用）、`ctx.log(...)` 写日志。

自带的技能：

| 名字 | 干什么 | 要模型 |
| --- | --- | --- |
| `echo` | 原样返回，验证链路 | 否 |
| `env.info` | Python / 系统 / 配置状态 | 否 |
| `plan.tasks` | 把一段话拆成任务 | 否（没配模型就用内置规则） |
| `reading.links` | 按关键词从内置文档目录推荐延伸阅读 | 否 |
| `learn.curriculum` | 学习目标 → 分阶段知识点路径（硬核目标先去抓教程大纲） | 否（没配模型就用内置模板） |
| `web.fetch` | GET 一个网页，返回去标签的正文 | 否 |
| `model.chat` | 直接问配好的模型 | 是 |
| `text.summarize` | 让模型总结一段文本 | 是 |
| `text.translate` | 让模型翻译 | 是 |
| `interest.suggest` | 兴趣标签的参谋：`mode=preset` 给一批预设方向，`mode=related` 按现有标签推 5 个相关的 | 否（没配模型就用内置词库） |
| `diagram.roadmap` | 知识点 + 依赖关系 → 一张能缩放、能导出的学习路线图 HTML（`diagrams/`） | 否 |

### 学习路线图（`diagram.roadmap` + Archify）

页面上不再手画 SVG：知识点写成**文本大纲**（存在 `goal.outline` 里），图只留后端 Archify 画的这一张**学习路线图**：

```powershell
python server.py --skill diagram.roadmap --params-file roadmap.json
```

`roadmap.json` 就三件事：标题、知识点数组、每层的名字。

```json
{
  "title": "学会写 LLVM 优化 pass：学习路线图",
  "level_labels": ["打基础", "看懂 pass", "分析能力", "动手改", "写自己的"],
  "nodes": [
    { "id": "ir", "title": "LLVM IR 与 SSA 形式", "short": "IR 与 SSA", "brief": "看懂 .ll 文件",
      "deps": [], "links": [{ "title": "LangRef", "url": "https://llvm.org/docs/LangRef.html" }] }
  ]
}
```

它做的事：按 `deps` 做最长路径分层 → 层内爬山排序把连线交叉压到最少 → 拼成 Archify 的 grid IR →
交给 `skills/vendor/archify` 校验并渲染。**同名重画会覆盖同一个文件**（上一轮的证据文件会先清掉，
否则 Archify 不肯覆盖）。

两处专门为「学习路线图」调过的地方：

- **细长链会折成蛇形几列**：一长串「一步接一步」的知识点（层数 > 6、每层又只有一两个）铺出来是根
  又窄又高的柱子，缩到页面上字就没了，所以折成 3 列的蛇形（读法是走完一列接着走下一列）。
  多层并列的图（比如某一层有 4 个知识点）保持原来的分层。
- **文字整体放大 1.2 倍**：成品的 `<head>` 里塞一段 `#roadmap-text-scale` 样式，把节点标题/副标题/
  角标和下面清单的字都放大。Archify 量「标签宽 ≤ 节点宽」时按 1.2em 算一个汉字（真实字宽 1em），
  正好留了这一份余量，所以不会压字。要更大可以传 `font_scale`（1.0~1.4）。
- 过不了校验时会**自己退档重试**：先按要求的 `cards` 来，不行退成只列标题，再不行把图例收起来
  （层数一多图例要好几排，会挤不下 `legend/vertical-overflow`）。

参数：

| 参数 | 说明 |
| --- | --- |
| `nodes` | 知识点数组：`{id, title, short, brief, deps, links, level}`；`short` 是节点里显示的短标签，不给自己裁 |
| `level_labels` | 每层的名字，会当节点角标和图例（不写就是「第 N 步」） |
| `cards` | 图下面的清单：`titles`（默认，只列标题）/ `links`（标题 + 教程链接，长了会自动退回 `titles`）/ `none` |
| `font_scale` | 文字放大倍数，默认 `1.2`，范围 1.0~1.4 |
| `name` | 输出文件名，默认从标题里的 ASCII 部分取（中文标题会变成 `roadmap-<哈希>`） |
| `quality` | `showcase`（默认，卡得严）/ `standard` |
| `candidate` | 直接给一份完整的 Archify architecture JSON，跳过上面的生成（高级用法） |

返回 `{ ok, url, file, gates, diagnostics, crossings, cards, legend, font_scale, seconds }`。`gates` 是 Archify 的四道门
（validate / deliver / check / browser-check），**`ok: true` 就代表四道全过**，交叉、标签压字、
视口溢出这些问题都被它量过了；没过就在 `diagnostics` 里给可测的数字。实测 15 个知识点约 3 秒。

它需要 **Node.js ≥ 18**（Archify 是 Node 写的），没装 node 会直接报错。第三方代码在
`skills/vendor/archify`（MIT，v3.0.1），许可证原文在那一层里。

### 技能怎么被用上

技能不是给人点的按钮，是**各功能内部调用的能力**。页面上没有「跑技能」的入口，接法是这样：

| 功能 | 技能 | 在哪接的 |
| --- | --- | --- |
| 目标页排学习计划 | `learn.curriculum` | `goals.js` 的 `skillPlan()`：模型没给出计划时调它，它也不行再退到内置模板 |
| 向导第三步出学习路线图 | `diagram.roadmap` | `goals.js` 的 `renderWizardDiagram()`：点「生成学习路线图」把当前知识点交给后端，回来后用 iframe 预览 |
| 设置页的兴趣标签 | `interest.suggest` | `settings.js`：进来推预设，选了标签再推 5 个相关的；后端不在就用本地词库 |
| 助手拆任务 / 问问题 | —（借后端的模型通道） | `tasks.js` 的 `bridgeChat()`：浏览器直连模型被跨域挡住时，改由后端代发 |
| 推荐阅读 | 前端内置目录（与 `reading.links` 同源） | 离线可用，不绕后端 |

要加一个「能力型」功能，就在 `skills/` 里加个 `.py`，再到对应功能的代码里调它：

```js
const data = await window.spasreBackend.run("技能名", { 参数: "值" });
```

命令行也能直接跑，不占端口（调试技能用）：

```powershell
python server.py --list-skills
python server.py --skill echo --params "{\"text\":\"hi\"}"
python server.py --skill plan.tasks --params-file params.json   # 中文参数写成文件更省事
python server.py --skill learn.curriculum --params-file goal.json
```

### 学习路径拆解（`learn.curriculum`）

把「学会 X」拆成分阶段的知识点路径。SKILL.md 里那两套方案合成了一套：**判断目标复杂度，再决定要不要先去找资料**。

- **判断**：命中编译器 / 硬件 / 竞赛算法 / 框架开发 / 机器学习等硬核领域关键词 → 判为专业目标；「学会 Git 基础」这类 → 通用目标。判断只看 `goal` 的文本，`level` 不参与判断（想强制先查资料就传 `mode: "research"`）。
- **通用目标**：直接用模型（没配模型就用内置模板）拆，不联网。
- **专业目标**：先去抓资料——调用方给的 `sources` → 内置领域书单 → DuckDuckGo 搜索，抓回来的页面**只取 `<h1>~<h4>` 标题**，正文一律不要（`headingsSample` 会带前 12 个标题出来，方便核验）。
- **拆解**：已知领域按内置的「教学顺序」模板走，检索到的、模板没覆盖的主题折成一个「资料补充主题」阶段挂在最后；未知领域才拿检索到的章节顺序来分组。多个教程合并去重，每个阶段标 `sources`。
- **兜底**：一份资料都没抓到 → 降级为模型原生拆解，输出开头写「未检索到权威教程，本次基于模型知识拆分，建议人工复核。」；模型也调不通 → 再降到内置模板，写「模型调用失败，本次改用内置模板拆分，建议人工复核。」。
- **粒度**：单个知识点 1~3 小时（`hoursPerUnit` 默认 2），带类型【概念 / 实操 / 刷题】、验收标准、前置依赖（前置指向不存在的知识点会被丢掉）。

参数（body 即参数）：

| 参数 | 说明 |
| --- | --- |
| `goal` | 学习目标，必填 |
| `mode` | `auto`（默认，硬核才检索）/ `direct`（只拆不检索）/ `research`（强制检索） |
| `level` | 当前基础，**自由文本**（例如「会写 C++，没碰过编译器」），会作为「当前基础」带进模型提示；它不是枚举，也不影响硬核判断 |
| `hoursPerUnit` | 单个知识点小时数，夹到 1~3，默认 2 |
| `maxUnits` | 知识点上限，夹到 4~60，默认 24 |
| `weeklyHours` | 每周投入小时，用来算阶段周数 |
| `sources` | 自己指定资料网址（数组或换行分隔的文本），给了就优先抓这些 |

返回里除了 `stages` / `stats` / `sources` / `warnings`，还带一份渲染好的 `markdown`，可以直接贴到目标页或记事本里。

### 前端怎么接的

`assets/js/backend.js`（挂在 `window.spasreBackend`）是前端 ↔ 后端的桥，页面上没有属于它的 UI：

- 探测后端（`/api/health`），并广播 `spasre:backend` 事件——助手卡片据此显示「本机后端在线」；
- 浏览器里有配置就推给后端；浏览器里没有、后端存着就拉回来（换浏览器、清过站点数据都不用重填）；页面开着时每几秒对一次，改了设置自动同步；
- 把后端能力交给功能调用：`run(技能)` / `chat(messages)` / `ask(text)`。

```js
await spasreBackend.available();          // 后端通不通
await spasreBackend.sync();               // 前端配置 → 后端
await spasreBackend.pull();               // 后端配置 → 浏览器
await spasreBackend.test();               // 测后端存的接口
await spasreBackend.chat("你好");          // 走后端调模型（绕开 CORS）
await spasreBackend.ask("帮我排这周");      // 走后端拆任务
await spasreBackend.skills();             // 技能清单
await spasreBackend.run("echo", { text: "hi" });
```

`.env` 里有明文密钥；`os.chmod` 在 Windows 上不一定生效，别把这个文件同步到公开的地方。

任务那边配套的日程接口：

```js
spasreTasks.segments();                // 一天切成哪几段 [{key,start,end}]
spasreTasks.checkSegments(list);       // 只校验、不动数据：合法返回 ""，不合法返回一句提示（重叠时就是「时间段有冲突」）
spasreTasks.clashKeys(list);           // 哪几段跟邻居叠了（网格拿它把那几行标红）

spasreTasks.segment("evening");        // 取一段
spasreTasks.segmentMinutes("evening"); // 这段多长（分钟）
spasreTasks.slotHours("evening", 3);   // 3 小时放不进这段 → 按段长收窄
spasreTasks.segmentOrder();            // 排期的偏好顺序（从晚到早）
spasreTasks.busy();                    // 被划成非空闲的段 ["2026-10-15:forenoon"]
spasreTasks.setBusy(date, key, true);  // 划掉 / 放开一段
spasreTasks.slotTime("evening", 2.5);  // 一段里放两小时半 → "19:30–22:00"
spasreTasks.slotPassed(date, "morning"); // 这一段（按结束时刻算）过去了没
spasreTasks.overdue();                 // 过期没做的知识点 ["目标id/节点id"]
spasreTasks.locked();                  // 被过期前置挡住、暂时不该做的节点
```

## 配色

底色是**冷调蓝白**，点缀是**蓝 + 粉**：蓝给主按钮和标题，粉给完成态、推荐开关和兴趣标签，
另加五种马卡龙强调色，顶栏那条线是**蓝 → 粉的双色渐变**。

| 变量 | 颜色 | 用在哪 |
| --- | --- | --- |
| `--brand` | **蓝** | 主按钮、正文标题 |
| `--leaf` | **粉** | 完成态、推荐开关、本地推荐卡片、飘落花瓣 |
| `--blue` | 马卡龙天蓝 | 「学习」分类、今日任务区块、向导当前步骤 |
| `--teal` | 马卡龙薄荷 | 「工作」分类、向导已完成步骤 |
| `--sakura` | **樱花粉** | 「生活」分类、推荐卡片、兴趣点标签、面板/弹层底色 |
| `--violet` | 马卡龙丁香紫 | 「每日推荐」分类、AI 推荐卡片、目标卡片 |
| `--peach` | 马卡龙蜜桃 | 其它分类（按名字散列）、「重要」紧急度 |
| `--grad-duo` | **蓝 → 粉双色渐变** | 顶栏下沿细线（半透明）、页面标题下划线、区块标题下划线、目标进度条 |
| `--paper` / `--ink` | 冷白 / 蓝灰 | 页面底色与正文 |
| `--danger` / `--ok` | 红 / 蓝 | 逾期、已完成 |

**按钮保持素净**：右下角加号和站点标记走 `--grad-brand`（蓝 → 粉），不参与双色渐变以外的花样。

**任务卡片**：左边框用分类色，卡片底色是同一颜色的淡染，而且**列表从上到下越来越浅**——`taskItem()` 按位置算出 `--tint`（第一条 0.26，每条减 0.035，最低 0.05），CSS 用 `rgba(var(--accent-rgb), var(--tint))` 铺一层渐变。

**日程表的任务块**：`--sched-rgb` 按目标顺序取五种强调色之一（同一目标同色），样式在 `.sched-chip`。

**飘落花瓣**：颜色在 `assets/js/site.js` 的 `palette` 里，八种（樱花粉 / 蜜桃 / 柠檬 / 薄荷 / 天蓝 / 丁香 / 深粉 / 湖蓝）。

- 每个强调色都有 `-soft`（淡底）、`-line`（描边）和 `-rgb`（给 `rgba()` 用的分量）三个衍生值，明暗主题各一套。
- 分类配色表在 `assets/js/tasks.js` 的 `CATEGORY_ACCENT`（学习=1、工作=2、生活=3、每日推荐=4），其它分类按名字散列到 1~5。

### 右下角按钮的位置

「回到顶部」和「＋」共用一组几何变量，**都是同宽 + 同一个 `right`**，所以圆心天然在同一竖线上（窄屏改 `--dock-size` / `--dock-right` 也一起变）：

```css
:root { --dock-size: 54px; --dock-right: 22px; --dock-bottom: 22px; --dock-gap: 14px; }
```

- 加号在下方 `--dock-bottom + --dock-size + --dock-gap` 处，正好排在「回到顶部」上方。
- 加号的图标是内联 SVG（不是全角 `＋` 字符），所以视觉中心严格居中。
